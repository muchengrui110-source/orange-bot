# 打包与脱敏：把源码整理成能发出去的包

这套流程解决的问题：手上跑着一套能用的东西，里面塞满了自己的号、路径、密钥、聊天数据，要发给别人或者公开，怎么保证不漏。

结论先放这：**脱敏不是最后扫一遍，而是打包流程的一部分**。红线写成清单，扫描脚本进版本库，每次打包重跑，漏一条就重做。

## 一个包的形状

每个包是一个自包含目录 + 一个同名 zip。目录里解压即用：

```
<包>/
  NEXT-AI.md      给「下一个 AI」看的避坑说明书（最重要的交付物）
  README.md       给人看的安装说明，短，200 行内
  install.ps1     一键落位（幂等，UTF-8 带 BOM，不覆盖已有配置）
  PACK-INFO.txt   版本、体积、打包时间、自检结果、内容清单
  docs/           本包专题文档（脱敏后才放）
  <内容目录>/      plugin/、napcat/、engine/、voice/ 之类
```

`NEXT-AI.md` 不是可选项。一个包最贵的不是代码，是「为什么这么接、哪一步会炸」这些只有踩过才知道的东西；不写下来，下次换个人（或者换个 AI）要从头踩一遍。

## 脱敏红线

包内任何文件（含 zip 里的）不得出现：

| 类别 | 例子 | 替代写法 |
|---|---|---|
| 账号 | 真实 QQ 号、手机号、邮箱 | `10001`、`user@example.com` |
| 人名/角色名 | 真名、昵称、角色名 | 「示例角色」 |
| 个人路径 | `<个人目录>\NapCat`、`C:\Users\<真名>` | `<DSH_HOME>`、`%USERPROFILE%`、`D:\tools\...` |
| 密钥 | OneBot token、API key、密码 | 空值 + 注释「自己填」 |
| 私人数据 | `personas.json`、`settings-ui.json`、`sessions.json`、日志、数据库、二维码 | 只给 `.example` 模板 |
| 个人音色 | `*.breeze`、参考录音、生成的 mp3 | 不给，用户自己录 |
| 模型权重 | 2.4G / 3.4G 的 gguf | 给下载脚本，校验 sha256 |
| 运行时配置 | `napcat/config/*_<号>.json`（含 token） | `config.example/`，首次启动重建 |

判断标准很土但好用：**这段东西贴到公开仓库，我会不会难受**。会，就别放。

## 工具链

`tools/` 下四个东西，都是打包时用的：

| 文件 | 作用 |
|---|---|
| `scan-secrets.ps1` | 扫包目录：给定关键词（账号、人名、个人路径）+ 禁止文件类型，0 命中才算过 |
| `verify-pack.ps1` | 终验：目录/zip 是否齐、zip 条目名有没有命中、ps1 语法和 BOM、禁止文件、体积和行数汇总 |
| `build-plugin.cjs` | 从运行中的 profile 里把插件本体和依赖收出来，去掉运行时产物 |
| `PACK-SPEC.md` | 规范原文：结构、红线、NEXT-AI 要求、README 要求、install 要求 |

扫描脚本的用法：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\scan-secrets.ps1 -Root "<包目录>"
# 输出 OK: 0 命中 才算过；exit code 非 0 = 有命中
```

关键词清单要**按自己情况改**：把真号、真名、真路径填进去。脚本是死名单，不是智能检测——它能挡住重复犯的错，挡不住新出现的私人信息，所以还得人看一眼。

## 流程

1. **定版本和来源**。每个包写清楚源码真身在哪、依赖从哪来、版本号钉死。别用「最新版」，打包当天是什么就记什么。
2. **收内容**。插件本体、脚本、示例配置、文档。运行时产物（日志、缓存、数据库、二维码）一律不收。
3. **脱敏**。按上面那张表逐条替换。示例配置全部改成假值。
4. **跑扫描**。`scan-secrets.ps1` 0 命中。有命中就回去改，别在扫描脚本里加白名单糊弄。
5. **语法和编码自检**。所有 `.ps1` 过一遍 parser；含中文的必须是 UTF-8 带 BOM。
6. **打 zip**。`tar.exe -a -c -f` 或 `Compress-Archive`。zip 放包目录同级。
7. **抽查解压**。解到临时目录，确认 `NEXT-AI.md`、`README.md`、`install.ps1` 在根，内容目录齐，**zip 条目名**里没有私人信息（文件名也会漏）。
8. **终验**。`verify-pack.ps1` 全 PASS，把结果写进 `PACK-INFO.txt`。
9. **备份两份**。成品别只放一个地方。

## 踩过的坑

- **PS 5.1 按 GBK 读文件**。用 `Get-Content`/`Set-Content` 绕一圈改 UTF-8 源码，写回去整份乱码，不可逆。改源码只走编辑器或能指定编码的 API。
- **BOM 不是可选的**。含中文的 `.ps1` 没 BOM，`powershell -File` 直接报语法错，报错位置还很靠后，看着像逻辑错。
- **zip 条目名也会漏**。目录名、文件名里带真号一样是泄露。所以终验要扫 zip 里的条目名，不只扫解压后的内容。
- **示例配置要能跑**。假号 + 空 token + 固定端口，用户改两行就能用；给个「见文档」的空文件等于没给。
- **install.ps1 要幂等**。用户会重复跑。已存在的配置打印「保留不动」，不要覆盖；加 `-Force` 才覆盖。
- **install 别自动扫码、别自动装插件**。扫码要人看着，装插件要人选包名——自动做只会半截失败还不好排查。
- **大文件别进 git**。单文件 100MB 是硬限，超了直接推不上去；几百 MB 的运行时放 Releases，仓库里留下载说明。
- **打包完重跑扫描**。中途改过文档就要重扫，别信「刚才扫过了」。
- **只存一处等于没存**。成品包、原始文档至少两个位置；桌面目录被清理工具误删过一次，找不回来。

## 验收清单

```
[ ] scan-secrets.ps1 0 命中
[ ] 所有 .ps1 语法 0 错误，含中文的有 BOM
[ ] 所有 .json 能解析
[ ] 无 *.log / *.db* / personas.json / settings-ui.json / sessions.json / *.breeze / *.mp3
[ ] zip 条目名无私人信息
[ ] zip 解压根目录含 NEXT-AI.md / README.md / install.ps1
[ ] PACK-INFO.txt 记了体积、文件数、自检结果
[ ] 有个干净机器（或空 profile）装一遍，能跑
```
